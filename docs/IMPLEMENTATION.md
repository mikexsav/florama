# Реализация и проверка требований

Документ связывает пользовательские сценарии с модулями проекта. Он не заменяет
README: команды запуска и порядок проверки находятся в корне репозитория.

## Аккаунт и данные пользователя

- `backend/auth.py`: OTP привязан к режиму регистрации/входа, действует пять
  минут, имеет лимит попыток и удаляется после успешной проверки.
- Сессия хранится на сервере; браузер получает случайный токен в `HttpOnly` cookie.
- Изменяющие запросы с cookie требуют CSRF-токен. Проверяется допустимый Origin.
- Проекты, полигоны, задания и анализы фильтруются по `user_id`.
- Миграции SQLite выполняются без удаления существующих аккаунтов.

## Участки

- ручное рисование с крупной начальной точкой для замыкания контура;
- поиск OpenStreetMap/Nominatim и сельскохозяйственных объектов Overpass;
- GeoJSON, WKT, bbox и атомарная загрузка до 50 участков из CSV;
- кадастровый номер сохраняется в паспорте, границу можно импортировать из
  официального источника пользователя;
- геометрия валидируется, площадь считается геодезически в WGS84.

## Спутники, ИК и погода

- Earth Search STAC предоставляет Sentinel-2 L2A COG;
- SCL-классы облаков/теней исключаются до агрегации;
- на общей сетке рассчитываются NDVI, EVI, NDMI, NDRE, BSI и false-color;
- сохраняются идентификатор сцены, даты, каналы, маска, масштаб, покрытие и
  предупреждения источников;
- Open-Meteo/ERA5 запрашивается по центроиду участка и тому же диапазону дат.

## Аналитика и восстановление

- наблюдаемые и восстановленные точки различаются в API и интерфейсе;
- сезонная норма строится по предыдущим годам без соединения разных сезонов;
- аномалия требует наблюдаемого спутникового подтверждения;
- batch-инференс полностью маскирует динамические признаки контрольной строки;
- универсальная модель дополняется экспертами Sentinel-2, Landsat и MODIS;
- OOF-валидация разделяет поля, а seeds, версии и хеши сохраняются в отчётах;
- формат выгрузки проверяется до записи и покрыт тестами.

## Эксплуатация

- API и worker разделены, поэтому долгий спутниковый запрос не блокирует HTTP;
- все ответы получают `X-Request-ID`, необработанные исключения журналируются;
- сбой одного внешнего источника сохраняется как предупреждение, а не заменяется
  выдуманными измерениями;
- локальный стенд запускается одной Docker Compose-командой;
- VPS-конфигурация содержит systemd, nginx, отдельный файл секретов и smoke-тест.

## Ограничения

Точный химический состав почвы и фитопатологический диагноз нельзя достоверно
получить только из Sentinel-2. Интерфейс показывает спектральные индикаторы и
рекомендацию полевой проверки. Анонимизированный train не содержит координат,
поэтому лаборатория использует условную воспроизводимую сетку, а не ложную карту.
